# 仕様: 複数タブ / 2画面（分割表示）

対象: 次期Plus機能
状態: フェーズ1〜5まで実装済み（残りはフェーズ6: ユーザーガイドの更新など）

## 1. 決定事項（前提）

| 論点 | 決定 |
| --- | --- |
| ペインの単位 | **ペインは「フォルダツリー＋タブ列＋ファイル一覧」の完結した1組**。2画面時は左右に2組並ぶ |
| タブ列 | **ペインごとに独立**。タブはドラッグで並べ替え・ペイン間移動ができる |
| 表示列の設定（表示/非表示・並び順・列幅） | **全ペイン・全タブ共通**（settings.json の構造は現状維持） |
| 起動時の復元 | **する**（タブ構成・分割状態・アクティブタブを保存し次回復元） |
| 提供区分 | **どちらもPlus機能**。未購読時は1ペイン1タブ（＝現在の見た目） |

補足: ツリーは「ペイン」に属し、「タブ」には属さない。同一ペイン内でタブを切り替えると、そのペインのツリーの選択がタブの現在パスへ同期される（展開状態はペイン内で共有）。

## 2. 用語

- **ペイン (Pane)**: ツリー・タブ列・ファイル一覧を1組にした表示単位。最大2つ。
- **タブ (Tab)**: 1つの閲覧状態（現在パス・戻る/進む履歴・検索語・All Filesモード・一覧のソート順）。
- **アクティブペイン**: 最後にフォーカスを得たペイン。メニュー操作（CSV書き出し等）の対象。
- **アクティブタブ**: 各ペインで表示中のタブ。

## 3. 機能仕様

### 3.1 タブ

- 位置: 各ペインの最上段に1行（ツリーと一覧の両方をまたぎ、ナビゲーション欄・検索欄より上）。タブごとにアドレス欄の内容も変わるため、ブラウザーと同じくタブ列を一番上に置く。タブが1つだけのときも表示する（購読者は常にタブ列あり）。
- タブの表示名: 現在フォルダ名。仮想ノード（Folders / ★ Favorites / 🕘 Recent / 🕒 Frequently Used）は対訳表の表示名。ドライブ直下は `D:\` のように表示。ツールチップはフルパス。
- 幅は上限つきの可変幅。溢れたら横スクロール（左右のスクロールボタン）。
- タブごとに保持する状態
  - 現在パス / アドレス欄の入力
  - 戻る・進む履歴
  - 検索語（インクリメンタルサーチの状態）
  - All Filesモード（フラット表示）のON/OFF
  - 一覧のソート列・昇降順
- タブをまたいで共有する状態: 表示列・列幅・列順、隠し/システム属性の表示、テーマ、言語、ルート設定、除外パス、お気に入り・履歴データ。

#### 操作

| 操作 | 方法 |
| --- | --- |
| 新しいタブ | タブ列右端の `+` / `Ctrl+T`（現在パスを複製して開く） |
| 新しいタブで開く | ツリーのフォルダ右クリック → 「新しいタブで開く」／ 一覧のフォルダ行を中クリック・右クリックメニュー |
| もう一方のペインで開く | ツリー／一覧の右クリック → 「反対側のペインで開く」（分割表示中のみ有効） |
| タブを閉じる | タブの `×` / 中クリック / `Ctrl+W` |
| タブ切り替え | クリック / `Ctrl+Tab`・`Ctrl+Shift+Tab` / `Ctrl+1`〜`Ctrl+8`（`Ctrl+9` は末尾タブ） |
| 並べ替え | タブをドラッグ |
| ペイン間の移動 | タブを反対のペインのタブ列へドラッグ（初回リリースに含む） |
| 閉じたタブを開き直す | `Ctrl+Shift+T`（初回リリースに含む） |

- 最後の1つのタブは閉じられない（`×` を出さない）。
- 1ペインあたりのタブ上限は **20**。上限に達したら `+` を無効化する。

#### タブのドラッグ

- ドラッグ開始のしきい値は `SystemParameters.MinimumHorizontalDragDistance`（クリックとの誤爆を防ぐ）。
- 同一ペイン内では挿入位置のインジケーター（縦線）を出しながら並べ替える。
- 反対ペインのタブ列へドロップすると、**タブVMのインスタンスをそのまま移す**（現在パス・履歴・検索語・モードを保ったまま移動する）。移動元が空になる場合は移動させない（最後の1タブは持ち出せない）。
- 移動先が上限20に達している場合、および移動元が空になる場合はドロップを受け付けない（ドラッグ中のカーソルが「不可」になる。アプリにステータスバーが無いため、メッセージは出さない）。
- ドロップ後は移動したタブをアクティブにし、そのペインをアクティブペインにする。
- タブ列の外（ウィンドウ外や一覧の上）へのドロップは何もしない（別ウィンドウへの切り離しはスコープ外）。

#### 閉じたタブの復元（`Ctrl+Shift+T`）

- 閉じたタブのスナップショット（パス・All FilesモードのON/OFF・戻る/進む履歴・閉じたペイン・閉じた位置）を**アプリ実行中のみ**最大10件、スタックで保持する。settings.json には保存しない。
- 復元先は閉じたときのペイン。そのペインが存在しない（分割OFF後）場合はアクティブペインの末尾へ。
- 元の位置に挿し込み、復元したタブをアクティブにする。
- 上限20に達している場合は何もしない（スタックからは取り出さない）。
- Plus未購読の間は無効。

### 3.2 2画面（分割表示）

- メニュー → 「分割表示」（トグル）。既定は左右分割。
- 分割方向は「左右」「上下」を選べる（メニューのサブ項目）。
- 中央の `GridSplitter` で比率を変更でき、比率は保存する。
- ONにしたとき、右（下）ペインは左（上）ペインのアクティブタブと同じパスのタブ1つで開始する。
- OFFにしたとき、非アクティブ側ペインのタブは**アクティブ側ペインの末尾に移動**する（閲覧中の状態を失わせない）。上限20を超える分は古いものから閉じる。
- アクティブペインは細い枠線で示す（テーマ追従のアクセントブラシ）。フォーカス移動で切り替わるほか `F6` でも切り替える。
- ペインごとに独立するもの: ツリー（展開・選択状態）、タブ列、アドレス欄、検索欄、All Filesトグル、ファイル一覧。
- ペインをまたいで共有するもの: ルート設定・除外パス・表示列・お気に入り／履歴・スキャン状態。

#### ウィンドウとペインの最小サイズ

1ペインの下限を「ツリー200px＋スプリッター4px＋一覧の実用下限320px＝約524px」とし、そこから次の値を設定する。

| 状態 | `MinWidth` | `MinHeight` |
| --- | --- | --- |
| 分割なし | 560 | 400 |
| 左右分割 | **1080** | 400 |
| 上下分割 | 560 | **700** |

- 分割の切り替え・方向変更のたびに `Window.MinWidth` / `MinHeight` を入れ替える。
- 分割ONにしたとき現在のウィンドウが最小値より小さければ、**最小値まで自動で広げる**（`SystemParameters.WorkArea` を超えない範囲。作業領域のほうが狭ければ作業領域いっぱいにする）。
- ペイン内では、ツリー側の列に `MinWidth="120"`、一覧側の列に `MinWidth="240"` を設定し、ペイン内スプリッターで一覧を潰せないようにする。
- 分割用スプリッターは、片側のペインが上表の1ペイン下限（524px／上下分割時は高さ260px）を切る位置まで動かせないようにする。
- 作業領域が1080pxに満たない環境（狭いノートPC等）では左右分割メニューを押した時点で作業領域幅まで広げ、`MinWidth` はその幅に丸める（ウィンドウが画面外へはみ出すのを防ぐ）。

### 3.3 ファイル・フォルダのドラッグ&ドロップ

本アプリはコピー／移動機能を持たないため、**ペイン間のドラッグ&ドロップによるファイル操作はスコープ外**とする（将来検討）。

### 3.4 スキャンとの関係

- フルスキャンはこれまでどおりアプリ全体で1本（`MainWindow.Scanning.cs` の `_fullScanCoalescer`）。ペインごとには走らせない。
- フォルダ単位スキャンは、スキャン中のパスをシェル側（アプリ全体）で保持し、両ペインの同一パスのノードに回転インジケーターを出す。
- スキャン完了後の一覧再読み込みは、**両ペインのアクティブタブ**のうち対象パス配下を表示しているものに対して行う。非アクティブタブは次にアクティブになった時点でキャッシュから読み直す。

### 3.5 Plus（購読）による出し分け

未購読（購読期限切れ含む）の場合:

- タブ列を表示しない（＝現在と同じ1画面1タブ）。
- メニューの「分割表示」は表示するが薄字で選べない（CSV書き出しと同じ扱い）。
- `Ctrl+T` などのショートカットは無効。
- 保存済みのタブ構成・分割状態は**消さずに無視**する（再購読で元に戻る）。復元するのは先頭タブ1つだけ。
- ライセンス確定前（起動直後）は未購読として扱い、`ApplyPlusFeatures()` の中でタブ列・分割の有効化を行う。

## 4. 永続化（settings.json）

`AppSettings` に以下を追加する。既存キーは変更しない。

```csharp
/// <summary>2画面（分割表示）が有効か。</summary>
public bool IsSplitViewEnabled { get; set; }

/// <summary>分割方向（"Vertical"=左右 / "Horizontal"=上下）。nullは既定＝左右。</summary>
public string? SplitOrientation { get; set; }

/// <summary>分割時の1つ目のペインの比率（0.1〜0.9）。nullは既定＝0.5。</summary>
public double? SplitRatio { get; set; }

/// <summary>アクティブなペインの番号（0 or 1）。</summary>
public int ActivePaneIndex { get; set; }

/// <summary>ペインごとのタブ構成（要素0が左/上、1が右/下）。nullは未設定＝1ペイン1タブ。</summary>
public List<PaneStateSettings>? Panes { get; set; }
```

```csharp
public sealed class PaneStateSettings
{
    public List<TabStateSettings> Tabs { get; set; } = new();
    public int ActiveTabIndex { get; set; }
}

public sealed class TabStateSettings
{
    /// <summary>現在パス（仮想ノードは "::Recent::" のような仮想パス）。</summary>
    public string Path { get; set; } = string.Empty;

    /// <summary>そのタブのAll Filesモード。</summary>
    public bool IsFlatFileViewEnabled { get; set; }
}
```

- 検索語・戻る/進む履歴は保存しない（起動時に検索状態を復元すると意図が伝わりにくいため）。
- 既存の `AppSettings.IsFlatFileViewEnabled` は**新規タブの既定値**として残す。既存の settings.json からの移行は「その値で1タブを復元する」だけで済む。
- 保存タイミングは既存の `SaveSettings(rootPaths)` に一本化する（タブの開閉・切り替え・分割の切り替え・比率変更の確定時に呼ぶ）。
- 復元時に存在しないパスがあってもタブは開き、キャッシュ由来の一覧を表示する（切断中のNASを想定。既存の `LoadFilesInternal` の方針と同じ）。全タブが復元できない場合は先頭ルートで1タブを開く。

## 5. アーキテクチャ（実装方針）

現状の `MainWindowViewModel` は「アプリ全体の状態」「ツリー」「1つの閲覧状態」を1クラスに同居させているため、これを3層に分ける。DIコンテナは引き続き使わず、`new` での組み立てを踏襲する。

```
MainWindowViewModel（シェル：改名せず既存クラスを縮小）
  ├ 設定・リポジトリ・ライセンスゲート・フルスキャン・お気に入り/履歴データ
  ├ Panes: ObservableCollection<BrowserPaneViewModel>（1〜2件）
  └ ActivePane

BrowserPaneViewModel（ペイン）
  ├ ツリー: RootFolders / TreeRoots / 仮想ノード（AllRoots・Favorites・Recent・Frequent）
  ├ Tabs: ObservableCollection<BrowserTabViewModel>
  └ ActiveTab

BrowserTabViewModel（タブ）
  ├ CurrentPath / AddressInput / SearchQuery / IsFlatFileViewEnabled / FileItems
  ├ 戻る・進む履歴
  └ 4つの SingleFlightCoalescer（_refreshCoalescer / _searchCoalescer / _folderSizeCoalescer / _flatViewCoalescer）
```

移行対象の目安（partialファイル単位）:

| 現在のファイル | 移動先 |
| --- | --- |
| `MainWindowViewModel.Navigation.cs` / `.Search.cs` / `.FlatView.cs` / `.FileItems.cs` / `.Cache.cs` | `BrowserTabViewModel.*.cs` |
| `MainWindowViewModel.Favorites.cs`（ノード生成・`RebuildTreeRoots`） | `BrowserPaneViewModel.Tree.cs`（データ本体はシェルに残す） |
| `MainWindowViewModel.Settings.cs` / `.Scanning.cs` | シェルに残す |

要点:

- **リポジトリはシェルが1つずつ持ち、ペイン／タブへ渡す**（`FileCacheRepository` は SQLite への並行アクセス前提で作られており、複数タブから同時に読んでも問題ない。マイグレーションが競合しないよう、生成はシェルの1箇所に限る）。
- **お気に入り・アクセス履歴のデータはシェルの単一の真実**。ペインは自分のツリー用ノードVMを組み立てるだけで、更新はシェルからのイベントで両ペインへ伝える。
- **`FolderItemViewModel.AttributesToSkip` は静的（アプリ全体で1つ）のまま**。変更時は全ペインのツリーに対して `Reload()` を呼ぶ。
- タブの `FileItems` はフラット表示で数十万件になりうるため、**非アクティブタブは一覧の実体を解放**し、アクティブになった時点でキャッシュから読み直す（キャッシュ由来の初期表示は元々高速なため体感差は小さい）。保持するのはパス・検索語・モード・履歴・ソート順のみ。

### 5.1 View側

- `MainWindow.xaml` のツリー＋一覧の部分を `Views/BrowserPaneView.xaml`（`UserControl`）へ切り出し、`DataContext` を `BrowserPaneViewModel` にする。`MainWindow` はメニュー＋ペインのホストだけを持つ。
- 現在 `MainWindow.FileListColumns.cs` が `x:Name` の列（`NameColumn` 等）を直接参照しているため、**列の見出し・表示/非表示・並び順・列幅の適用ロジックを `BrowserPaneView` のコードビハインドへ移す**（インスタンスごとに同じ処理を走らせる）。列設定の値はシェル（`MainWindowViewModel`）から取得し、値そのものは全ペイン共通。
- 列幅の保存は「アクティブペインの一覧の現在値」を保存する。分割時に左右で違う幅にドラッグしても、保存されるのは最後に触ったペインの値（＝共通設定）。この挙動はユーザーガイドに1行明記する。
- タブ列は `TabControl` ではなく `ItemsControl` + ヘッダーの自作で実装する（`TabControl` は非アクティブタブのコンテンツを破棄・再生成するため、一覧のスクロール位置やソート状態を保てないことがある）。一覧の実体は各ペインに1つだけ置き、`ActiveTab` のバインディングを差し替える。
- `MainWindow.Tree.cs` の `_treeItemMap`（パス→TreeViewItem）は**ペインごとに1つ**へ移す。現在の実装がウィンドウ単位のため、そのままでは2ペインで衝突する。

## 7. テスト方針

`Tests/ParallelScope.Tests` に追加する（UI非依存の層のみ）:

- `BrowserTabViewModel`: 履歴（戻る/進む/上へ）・検索とフラット表示の優先順位が現在の `MainWindowViewModel` と同じであること（既存テストの移植）。
- `BrowserPaneViewModel`: タブの追加/複製/クローズ/切り替え、最後の1タブは閉じられない、上限20。
- タブのペイン間移動（VMレベル。移動元が空になる移動は拒否、移動先が上限なら拒否）、分割OFF時のタブ吸収と上限超過分の破棄。
- 閉じたタブの復元: スタックが最大10件で古いものから溢れること、元の位置に戻ること、上限20のときは復元しないこと。
- 永続化: タブ構成の保存 → 再読み込みで同じ構成に戻る。存在しないパスを含む場合のフォールバック。
- Plusゲート: 未購読では復元が先頭タブ1つになり、保存済みの構成は settings.json から消えないこと。
- 既存の `PlusFeatureGatingTests` / `TreeNodeSettingsTests` の更新（ツリーがペイン側へ移るため）。

UI（タブのドラッグ、分割の見た目、キーボードショートカット）は自動テスト対象外。ビルド後の exe を起動して手動で確認する。

## 8. 実装フェーズ

1. **リファクタ（挙動不変）**: `MainWindowViewModel` から `BrowserTabViewModel` を抽出。タブ1つ・ペイン1つの構成で従来と同じ動作になることを確認。
2. **リファクタ（挙動不変）**: ツリー＋一覧を `BrowserPaneView` へ切り出し、列制御をコードビハインドごと移す。`_treeItemMap` をペイン単位へ。
3. **複数タブ**: 1ペイン内のタブ列・開閉・切り替え・並べ替えドラッグ・ショートカット（`Ctrl+T` / `Ctrl+W` / `Ctrl+Tab` / `Ctrl+1`〜`9` / `Ctrl+Shift+T`）・コンテキストメニュー。
4. **2画面**: ペインの複製・分割トグル・方向・スプリッター・最小サイズ制御・アクティブペイン表示・`F6`・「反対側のペインで開く」・**タブのペイン間ドラッグ**。
5. **永続化と復元**: `AppSettings` 拡張、保存/復元、移行。
6. **Plusゲート・ローカライズ・ユーザーガイド（docs/）更新・テスト追加**。

各フェーズの完了条件は「`dotnet build` が0警告0エラー」「`dotnet test` が全緑」「ビルドしたexeでの手動確認」。

## 10. 実装時に判断する細部

仕様としては固まっており、実装時に実機で詰める項目:

- タブ1つあたりの最小幅・最大幅（表示名が潰れない下限。目安 100〜240px）。
- タブのドロップ位置インジケーターの見た目（テーマ追従のアクセント色の縦線）。
- 分割スプリッターのつまみ幅（現在のツリー用スプリッターは4px）。
